# MSP Backup

Единый Python-инструмент для установки Restic и управления серверными резервными копиями. Поддерживает Debian/Ubuntu и RHEL-подобные системы с systemd.

## Установка

Скопируйте `msp-backup.py` и каталог `msp_backup/` на сервер в одну директорию и запустите:

```bash
sudo python3 msp-backup.py
```

Скрипту нужен Python 3.9 или новее. Приложение, пакет `msp_backup/`, конфигурация, секреты, логи, кэш Restic и Restic-бинарник размещаются в `/opt/msp-backup/`. До установки недостающих системных пакетов он попросит подтверждение. Проверяются FUSE и logrotate; для монтирования нужен `/dev/fuse`.

Файлы systemd unit и конфигурация logrotate хранятся в `/opt/msp-backup/systemd/`; в `/etc/systemd/system/` и `/etc/logrotate.d/` создаются символические ссылки, необходимые системным службам. При запуске из исходного проекта скрипт переносит старые настройки и секреты из `/etc/msp-backup/`, логи из `/var/log/msp-backup/` и Restic из `/usr/local/sbin/restic`.

Для шифрования секретов используется `systemd-creds`, если установлен systemd 250 или новее. На более старых системах скрипт предложит установить пакет `python3-cryptography` и использует Fernet. Зашифрованные значения и ключ fallback-режима находятся в `/opt/msp-backup/data/`. Ключ `credential.key` доступен только root (права `0600`). При переносе или восстановлении старого сервера сохраните отдельную защищённую копию ключа, например в Bitwarden. Поскольку ключ хранится на том же сервере, fallback защищает от доступа обычных пользователей, но не от копии всего диска или root-доступа.

## Возможности

- Настройка репозитория, путей, политики хранения и ежедневного systemd timer.
- Добавление, замена и удаление путей резервного копирования после настройки через **Settings → Backup paths**, без повторного мастера.
- Мастер для Amazon S3 и S3-совместимых хранилищ; смена адреса, bucket и ключей в **Settings → Repository / S3 settings**.
- Генерация уникального пароля Restic в мастере настройки; пароль нужно сохранить в Bitwarden до продолжения.
- Цветное ANSI-меню со стрелочной навигацией, прокруткой длинных списков и статусами операций в SSH-терминалах; результаты остаются на экране до нажатия клавиши. Для неинтерактивного запуска доступен цифровой ввод.
- Интерактивный список снимков: выбор снимка, восстановление целиком или отметка отдельных файлов и каталогов; перед восстановлением показывается план и запрашивается подтверждение.
- Запуск копий, проверка репозитория, монтирование и размонтирование снимков.
- Автоматическое обнаружение пользовательских MySQL/MariaDB и PostgreSQL баз; отдельный дамп каждой базы перед Restic backup. Для SQLite можно указать файл или каталог, в котором будут найдены базы по сигнатуре SQLite.
- Шифрование паролей Restic, СУБД и SMTP с временной расшифровкой в `/run` на tmpfs/ramfs.
- Логирование, настройка ротации через logrotate и SMTP-уведомления.
- Проверка и обновление самого MSP Backup по URL настраиваемого manifest.
- Проверка случайной выборки данных репозитория без локального восстановления; пробное восстановление одного файла с оценкой свободного места и автоочисткой временной копии.

## Структура проекта

Код разделён на пакет `msp_backup/`; `msp-backup.py` остаётся точкой запуска. `BackupApplication` собирает менеджеры и маршрутизирует команды. `BackupWorkflowManager` отвечает за мастер настройки, расписание, восстановление и монтирование; отдельные `ResticManager`, `ResticInstaller`, `DatabaseBackupManager`, `NotificationManager`, `UpdateManager`, `CredentialStore`, `ConfigStore` и `SystemManager` обслуживают свои области. Версия пакета хранится в `msp_backup/version.py`, а метаданные проекта и версия релиза — в `pyproject.toml`.

## Базы данных

Перед Restic backup скрипт создаёт логические дампы БД в `/run/msp-backup/db-dumps` и включает их в снимок. После успешного backup дампы удаляются; при неудаче частичные файлы тоже очищаются.

- **MySQL/MariaDB:** все пользовательские схемы автоматически обнаруживаются при каждом запуске; каждая сохраняется в отдельный SQL-файл с routines, events и triggers. Отдельный `mysql-users.sql` содержит определения аккаунтов и grants. Встроенные схемы `information_schema`, `performance_schema`, `mysql` и `sys` как данные не копируются. Для согласованности таблицы должны использовать InnoDB; MyISAM не фиксируется транзакционно.
- **PostgreSQL:** все базы, кроме template-баз, сохраняются по отдельности в custom-архивы `pg_dump`; глобальные роли и tablespaces — отдельно через `pg_dumpall --globals-only`. Это логический, не физический backup и не PITR.
- **SQLite:** можно указать отдельный файл или каталог. Для каталога рекурсивно находятся файлы с сигнатурой SQLite и каждый снимается через online backup в отдельный файл.

Временные дампы хранятся в `/run/msp-backup/db-dumps` (tmpfs/ramfs). Перед выгрузкой программа оценивает свободное место в `/run` и откажется начинать, если его недостаточно; при сбое частичные дампы удаляются. Поэтому для больших баз заранее проверьте доступный объём RAM/tmpfs. В отчёт о задании включается число обработанных баз.

Для восстановления выберите снимок и отдельный каталог на `/run` (tmpfs) или зашифрованный том. MySQL-файл базы импортируется через `mysql < mysql-ИМЯ.sql`; `mysql-users.sql` применяйте после баз на совместимой версии сервера. Для PostgreSQL сначала восстановите globals, затем создайте базы и примените каждый custom-архив через `pg_restore`. Полный импорт может менять существующие базы и роли; сначала проверьте его на тестовом сервере.

## Логи и уведомления

Лог находится в `/opt/msp-backup/logs/msp-backup.log`, а события также доступны через systemd journal. Каталог лога закрыт для других пользователей. По умолчанию logrotate ротирует его ежедневно и хранит 14 архивов; частоту и количество можно менять в меню.

SMTP настраивается через STARTTLS или SSL/TLS, с авторизацией и несколькими получателями. Режим **«Всегда»** отправляет письма после успешного backup и при сбое; **«Только при проблемах»** — только при сбое. Отчёт содержит сервер, время и длительность запуска, ID последнего снимка и выдержку из журнала systemd. Можно отправить тестовое письмо. Python использует стандартную SMTP-библиотеку, отдельный пакет для почты не нужен.

## Самообновление скрипта

В настройках укажите HTTPS URL JSON-manifest со следующими полями:

```json
{
  "version": "1.11.0",
  "url": "https://updates.example.com/msp-backup-1.11.0.zip",
  "sha256": "64-символьный sha256 ZIP-архива пакета"
}
```

При запуске MSP Backup проверяет manifest и предлагает установить более новую версию. Для публикации из корня проекта соберите архив командой `zip -r msp-backup-1.11.0.zip msp_backup` и посчитайте его SHA-256 командой `sha256sum msp-backup-1.11.0.zip`. Выложите архив и manifest на доверенный HTTPS-сервер. Перед установкой программа проверяет HTTPS URL, контрольную сумму, версию пакета и допустимые имена файлов; ZIP не может записывать файлы за пределы пакета. Можно также включить еженедельный systemd timer, который установит проверенное обновление. Бинарник Restic обновляется отдельно.

## Хранение секретов

- Пароли Restic, БД и SMTP находятся в зашифрованном виде в `/opt/msp-backup/data/`. Используется systemd credential encryption на systemd 250+ или Python Fernet fallback на более старых системах. Настройки подключения хранятся отдельно, без паролей.
- Последний отчёт о запуске хранится в `/opt/msp-backup/data/last-run.json` с правами root-only и содержит результат, время, длительность и ID снимка; паролей в нём нет.
- Для операций секреты кратковременно расшифровываются в `/run`, если он смонтирован как tmpfs/ramfs, затем удаляются. Дампы баз тоже создаются в `/run`.
- На systemd 250+ шифрование может быть связано с ключом хоста и, если доступен, TPM. В fallback-режиме ключ хранится в `credential.key` с правами root. Ни один режим не защищает от злоумышленника с root-доступом во время работы сервера.
- Сохраните исходные пароли в Bitwarden. При переустановке или переносе сервера могут потребоваться исходный TPM/системный ключ либо повторный ввод паролей.
- Скрипт пытается перевести известные plaintext-секреты старых версий в зашифрованные credentials и удалить исходники. Из-за SSD и журналируемых файловых систем `shred` не гарантирует стирание прежних блоков; если старые секреты попадали в резервные копии или образы, смените их.
- Не добавляйте пароль в URL репозитория. Для SFTP настройте SSH-доступ root и проверку host key.
- S3 Access Key, Secret Key и временный Session Token хранятся в отдельном зашифрованном файле `s3-credentials.cred`; на время операций ключи расшифровываются в защищённый каталог `/run` и передаются Restic через переменные окружения. Они не сохраняются в JSON-конфигурации и не передаются в аргументах командной строки.

## Настройка S3

В мастере установки выберите Amazon S3 или S3-совместимое хранилище. Для AWS укажите регион, имя bucket и необязательный prefix. Для совместимого сервиса укажите HTTPS endpoint, регион, bucket и prefix. Затем введите Access Key ID и Secret Access Key; временный Session Token можно указать дополнительно. MSP Backup сформирует адрес Restic автоматически. Для изменения хранилища после настройки откройте **Settings → Repository / S3 settings**. При повторной настройке пустые поля ключей сохраняют уже сохранённые значения; `-` в поле Session Token удаляет старый токен.

Главное меню объединяет действия по смыслу: просмотр снимков сразу ведёт к восстановлению; проверка репозитория, проверка выборки данных, пробное восстановление файла, монтирование/размонтирование и очистка по политике хранения находятся в **Snapshot tools**; ежедневное расписание и еженедельное автообновление — в **Schedules**. В **Settings → Backup paths** можно добавлять, заменять и удалять пути в любое время; путь дампов БД управляется автоматически и не удаляется, пока включено резервирование БД. Проверка выборки читает заданный объём данных непосредственно из репозитория и не восстанавливает файлы на локальный диск. Пробное восстановление проверяет свободное место, временно восстанавливает только один выбранный файл в существующий каталог и удаляет временную копию после проверки; выбирайте файл, который помещается на целевой раздел, либо отмените операцию. Остальные настройки репозитория, логов, SMTP и URL обновления собраны в **Settings**.

## Просмотр и восстановление снимков

В меню списка снимков выберите нужный снимок стрелками и нажмите Enter. Затем можно восстановить весь снимок или открыть список его файлов и каталогов: Enter отмечает выбранный пункт, а выбранный каталог восстанавливается вместе с содержимым. Для длинных списков доступны PgUp/PgDn; действие очистки снимает все отметки. Перед записью MSP Backup показывает снимок, область восстановления и целевой каталог, затем просит подтверждение. Восстановление запускается в отдельный абсолютный каталог и не удаляет лишние файлы в нём; совпадающие имена могут быть перезаписаны.
